# 报销三级审批

报销审批固定为三级审核，三级通过后由财务执行付款。审核人按**报销人所属部门**配置，每一级都可以配置多人，其中任意一人处理即可。

## 审批节点

| 节点 | 处理人 | 通过后 | 支持打回 |
| --- | --- | --- | --- |
| 待上传证明 | 报销人 | 上传付款截图和发票后手动提交，进入待一级审核 | 否 |
| 待一级审核 | 该部门配置的一级审核人 | 待二级审核 | 是 |
| 待二级审核 | 该部门配置的二级审核人 | 待三级审核 | 是 |
| 待三级审核 | 该部门配置的三级审核人 | 待执行 | 是 |
| 待执行 | 财务（finance）、管理员（admin） | 已执行 | 否 |

- 新建订单勾选个人垫付后，报销记录先进入“待上传证明”，不会直接出现在审核队列；员工在“我的报销”的附件列点击【上传】，补传付款截图和发票后点击【提交】才进入一级审核。
- 报销金额需要调整时，由报销人在“我的报销”点击【申请修改金额】并填写原因，不会直接改动订单成本。
  - 待上传证明、已打回：记录修改并标记“已修改”，后续提交时进入一级审核。
  - 待一级审核：保持一级审核，审核人可看到修改记录。
  - 待二级审核 / 待三级审核 / 待执行：分别退回一级审核 / 二级审核 / 三级审核重新审核；未归档单据号会在退回时清空，重新通过后按新金额生成。
- 修改过的报销在列表金额下方显示“已修改”，详情页展示修改原因、时间和审批记录。
- 审核人不能处理本人提交的报销，固定管理员 UID 走额外身份验证流程的既有机制保持不变。
- 每一级配置多名审核人时采用“任一人处理即可”，处理完成后该节点结束。
- 三级审核通过时自动生成报销单据；待执行节点确认后进入已执行，并进入历史报销。
- 任一审核节点打回后，报销回到“已打回”；报销人补传发票后重新从一级审核开始。

## 部门审核人配置

在“员工与权限管理 → 报销三级审批设置”中，按部门分别勾选一级、二级、三级审核人，保存后立即生效。对应接口为 `PATCH /api/department-approvers`，读取接口为 `GET /api/department-approvers`。

- 只有管理员、老板可以维护审批设置。
- 可选审核人为已启用的正式员工；不限其所属部门。
- 报销提交时会记录报销人当时的部门快照，之后员工调岗不会改变已提交报销的审批链；历史记录缺少部门快照时，按报销员工的档案部门补全，避免已配置审核人仍看到默认角色。
- 报销单据的“当前审核人”优先显示该部门当前节点实际配置的审核人姓名，只有该节点未配置时才显示默认角色。
- 部门某一级未配置审核人时，该级按默认角色兜底：
  - 一级：管理员、老板
  - 二级：财务
  - 三级：老板
  - 执行：财务

## 权限入口

- 被配置为任意部门任意一级审核人的员工，即使不是财务或老板，也能看到“报销审核”入口，并且只会看到自己负责的当前节点记录。
- 部门审核人可查看和下载其负责部门的报销附件与审批记录，不受财务/管理身份限制；非本部门审核人不能查看。
- 历史报销仍只对管理员、老板、财务开放。
- 单据生成、归档和报销导出仍限财务相关角色。
- 批量审核使用与单条审核相同的逐条授权检查，不能跨节点或处理他人节点。
- 所有审核、打回、重新提交和确认执行都会写入 `reimbursement_approvals`，并在报销详情中展示。
