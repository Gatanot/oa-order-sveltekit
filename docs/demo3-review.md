# `pics/demo3.html` 功能与交互审核

## 1. 文件定位

`pics/demo3.html` 是一个广告订单 OA 的完整前端原型，覆盖订单、报价/成本基础资料、员工报销和财务审核等流程。它适合作为当前 SvelteKit 项目的产品交互与功能参考，但不建议直接复制其单文件 HTML/CSS/JavaScript 实现。

## 2. 可借鉴的核心功能

### 2.1 页面与角色

- 左侧导航：订单列表、我的报销/报销管理、报价库与成本库。
- 当前身份切换：员工、财务管理员。
- 员工端与财务端根据角色显示不同的数据和操作。
- 订单列表 → 订单详情 → 新增/编辑订单，流程路径清晰。

### 2.2 订单列表

- 按开始日期、结束日期、客户、设计师、结款状态筛选。
- 支持订单/产品/联系人关键词搜索。
- 支持日期新旧、销售额排序。
- 筛选结果同步刷新统计卡片：销售总额、制作成本、员工垫付、预计毛利、未结款金额。
- 支持自定义表格字段：部门、联系人、设计师、制作状态、结款状态、制作成本、员工垫付、预计毛利。
- 点击表格行进入订单详情。

### 2.3 订单录入与编辑

基础信息包括：

- 客户
- 客户部门
- 联系人/下单人
- 下单日期
- 交货日期
- 指定设计师
- 开单员
- 订单状态

业务明细分为：

- 产品明细
- 固定厂商成本
- 员工垫付

动态行交互：

- 产品可增删；从报价库选择产品后自动带出单位、价格、制作要求。
- 成本可增删；从成本库选择项目后自动带出供应商、单位、成本单价。
- 员工垫付可增删，并支持发票文件选择。
- 数量、单价、小计和订单金额联动计算。

### 2.4 报销流程

完整状态流转：

```text
员工提交报销 → 待审核 → 审核通过 → 待打款 → 已报销
                         ↘ 打回 → 员工重新上传发票 → 待审核
```

员工端支持：

- 新增报销。
- 查看本人报销记录。
- 按日期、类型、状态筛选。
- 查看订单报销和内务报销。
- 查看打回原因。
- 重新上传发票。
- 查看已生成的报销单据。

财务端支持：

- 按日期、员工、类型、状态筛选。
- 查看指定员工的报销队列。
- 单条审核通过或打回并填写原因。
- 批量审核通过、批量打回、批量生成单据。
- 按员工汇总待打款单数和金额。
- 单员工确认已打款或批量确认已打款。
- 导出打款汇总。

### 2.5 报价库与成本库

- 报价库按公司维护。
- 成本库按厂商维护。
- 支持新增公司/厂商。
- 支持配置或上传报价/成本文件。
- 支持查看库明细和关键字搜索。
- 库数据参与订单录入时的产品、供应商、单价和制作要求联动。

### 2.6 视觉与响应式

- 深蓝色侧栏、浅灰背景、白色卡片。
- 蓝色主操作、灰色次操作、红色危险操作。
- 使用状态标签区分待审核、已打回、待打款、已报销等状态。
- 表格在小屏幕上横向滚动，不强行压缩字段。
- 移动端侧栏转为顶部导航。
- 表单控件高度、圆角、字号统一。

## 3. 不建议直接沿用的实现

- CSS 多次覆盖并大量使用 `!important`，迁移时应整理成设计变量、布局、组件、业务和响应式分层。
- 数据、渲染、事件和业务状态全部堆在单一 HTML 文件中，SvelteKit 中应拆成组件、store、服务和类型。
- 示例数据保存在内存变量中，刷新即丢失；正式实现应使用后端 API 和数据库。
- 文件上传实际只保存文件名，不是真正的文件存储。
- 发票下载和部分导出属于原型模拟，正式实现需要文件存储和服务端导出。
- 前端角色切换不能替代服务端权限校验。
- 原生字符串拼接 HTML 可维护性和安全性较差，Svelte 模板应使用声明式渲染。
- 原型中存在重复赋值、重复填充 select、临时选择器等代码质量问题，不能原样迁移。

## 4. 建议在当前 SvelteKit 项目中优先吸收的顺序

1. 先对齐现有布局、路由和数据模型。
2. 完成订单列表筛选、排序、金额统计和字段显示控制。
3. 完成订单详情、新增和编辑。
4. 将产品明细、成本明细、员工垫付拆成可复用动态行组件。
5. 接入报价库/成本库联动自动带出信息。
6. 实现员工报销列表和新增报销。
7. 实现财务审核、打回、批量操作和待打款汇总。
8. 实现单据生成、查看和导出。
9. 最后补齐响应式、空状态、提示、确认和错误处理。

## 5. 与当前 SvelteKit 项目的对照

当前项目已经具备以下 demo 能力：

- 订单总览、订单详情、新增/编辑订单。
- 订单日期、客户、项目、负责人、设计师、录入人、结款状态和关键词筛选。
- 销售额、成本、员工垫付、预计毛利和未结款统计。
- 动态产品、成本和员工垫付行。
- 报价/成本库 Excel 导入、搜索和订单录入联动。
- 订单附件和报销发票的真实文件上传、查看与持久化。
- 员工/财务视图切换。
- 报销筛选、批量确认、批量标记已报销、待付款员工汇总、明细查看和 Excel 导出。
- 订单 Excel 导出及导出列选择。

当前与 demo 的主要差距：

| 功能 | demo | 当前项目 | 吸收建议 |
| --- | --- | --- | --- |
| 报销打回 | 支持填写原因并打回 | 尚未支持 | 增加“已打回”和打回原因，员工可重新上传 |
| 员工端状态 | 待审核、已打回、待打款、已报销 | 待核验、待报销、已报销 | 统一为产品语义，保留兼容旧数据的映射 |
| 财务审核队列 | 先选员工，再查看该员工队列 | 直接显示筛选后的全量表格 | 增加员工选择和当前员工队列标题 |
| 单据 | 可生成编号、归档、查看和导出 | 由记录派生编号并可查看 | 增加明确的生成动作和 TXT/Excel 导出 |
| 订单列 | 可显示产品集合和业务金额字段 | 以订单主字段和项目维度为主 | 保留现有字段，同时加强产品/利润列展示 |
| 基础资料 | 公司/厂商分别管理 | 统一报价/成本库 | 在不破坏统一导入的前提下增加来源/供应商视图 |

## 6. 本轮实施重点

优先补齐对用户影响最大的报销闭环：

1. 财务可以单条或批量打回，并要求填写员工可见的原因。
2. 员工在“已打回”状态看到原因，可以重新上传发票。
3. 重新上传后记录回到“待核验”，财务可以再次审核。
4. 打回记录在员工端和财务端使用明显的红色状态样式。
5. 保持现有 SQLite、附件 API 和 Svelte 组件结构，不复制 demo 的单文件实现。

## 7. 迁移原则

以 `demo3.html` 作为功能和交互基准，以当前 SvelteKit 项目的路由、组件规范、数据访问方式和 UI 体系作为实现约束。目标是尽量复现 demo 的用户可见功能和操作反馈，而不是复制其代码结构。
