## 一、`src/hooks.server.ts` —— 允许被发布入口内嵌

```diff
-  response.headers.set('X-Frame-Options', 'SAMEORIGIN');
+  // 不发送 X-Frame-Options，也不发送 frame-ancestors
```

**原因**：CatsCo 的发布入口页面用 `<iframe sandbox="...">` 内嵌工作台。沙箱 iframe 的祖先来源是「不透明来源」（opaque origin），此时：

- `X-Frame-Options: SAMEORIGIN` 判定失败；
- `Content-Security-Policy: frame-ancestors ...` 无论取值（**包括 `*`**）也判定失败。

两种情况整帧都会被浏览器拦掉，工作台显示空白或错误。实测唯一可行的做法是**这两个头都不发**。

**影响面**：本工作台没有登录态、没有 Cookie 会话，「点击劫持」风险仅限展示层套框，可接受。若你们不需要内嵌发布，这一处可以不改。

> 注意：上游在这之后仍然保留了 `X-Frame-Options`，所以每次同步上游都会在这行产生冲突。

## 二、`src/routes/+page.server.ts` —— 首页跳转改为相对路径

```diff
-export const load: PageServerLoad = () => redirect(303, '/orders');
+export const load: PageServerLoad = () => redirect(303, './orders');
```

**原因**：在 Artifact 网关下，应用被服务在 `/<应用id>/` 前缀里，网关**剥掉前缀再转发**给应用，所以服务端看到的路径是 `/`，它并不知道浏览器那边的前缀。绝对路径 `Location: /orders` 会让浏览器跳出应用前缀，落到网关根 → 404。

改成相对 Location 后，浏览器按当前前缀解析：网关下是 `/oa-order-workbench/orders`，自有域名下是 `/orders`，两条通道都正确。

## 三、`src/lib/components/order-desk/orderDeskState.svelte.ts` —— 只在网关主机做登录握手

三处小改：

1. 文件顶部新增：

```ts
const ARTIFACT_GATEWAY_HOSTS = ["artifact.catsco.cc", "artifact.catsco.cn"];
function isArtifactGatewayHost(): boolean {
  return typeof window !== "undefined" && ARTIFACT_GATEWAY_HOSTS.includes(window.location.hostname);
}
```

2. `createOrderDesk` 内新增 `let onArtifactGateway = $state(false);`，并在 `onMount` 中赋值；握手条件加上该判断：

```diff
-    if (data.visitor.status === "guest" && !isEmbedded) {
+    onArtifactGateway = isArtifactGatewayHost();
+    if (data.visitor.status === "guest" && !isEmbedded && onArtifactGateway) {
       sessionStorage.setItem(handshakeKey, "started");
       window.location.assign("/_auth/start");
```

3. 导出 getter：`Object.defineProperty(desk, "onArtifactGateway", { get: () => onArtifactGateway });`

**原因**：上游逻辑是「游客 + 顶层窗口」就顶层跳转 `/_auth/start` 做握手。该端点只存在于 Artifact 网关，在自建域名直连时不存在，于是跳到一个不存在的路径，最终渲染成应用自己的错误页：

```
404
页面暂时无法显示
服务器内部错误
```

这正是实际遇到的现象。限定只在网关主机触发后，网关下握手行为不变，直连通道不再自跳 404。

## 五、配置侧（不在补丁里，但缺了身份就是不可用）

`.env` 增加：

```
ARTIFACT_APP_ID=<平台登记的应用id>          # 例如 oa-order-workbench
# ARTIFACT_GATEWAY_ORIGIN=https://artifact.catsco.cc   # 一般无需覆盖
```

- 应用 id 必须与平台登记一致，格式 `^[a-z][a-z0-9_-]{0,47}$`。
- 未配置或网关不认识这个 id 时，身份状态是 `unavailable`（接口返回 503），这是刻意设计的如实降级，不会伪装成游客。
- `ORIGIN` 必须等于浏览器实际访问地址，否则 adapter-node 会拒绝 Excel 与附件表单上传。
- 服务端把请求的 `cookie` / `authorization` 原样转发到网关 `/_gateway/me`，不解析票据；身份判定必须留在服务端。

平台侧登记（用 bot 自己的 key，归属才是这个 bot）：

```bash
# 1) 生成密钥并取 publicKey
node init-connector.mjs <状态目录> <应用id> artifact.catsco.cc 22443 \
  auto <本地端口> <SKILL_DIR>/connector/gateway_host.pub \
  wss://artifact.catsco.cc/_gateway/tunnel --agent $CATSCOMPANY_BOT_UID --title "显示名"

# 2) 登记
curl -sS -X POST "$CATSCOMPANY_HTTP_BASE_URL/api/artifacts/apps" \
  -H "Authorization: ApiKey $CATSCOMPANY_API_KEY" -H 'Content-Type: application/json' \
  -d '{"id":"<应用id>","title":"显示名","publicKey":"<上一步>","localPort":<本地端口>}'

# 3) 用返回的 remote_port 再跑一次 init-connector，然后常驻 connector.mjs
```

## 六、验证清单

```bash
# 网关入口：应为 303 后落到 /<应用id>/orders 且 200
curl -s -o /dev/null -w '%{http_code} %{url_effective}\n' -L https://artifact.catsco.cc/<应用id>/

# 身份端点：无凭据时是游客，不是报错
curl -s "https://artifact.catsco.cc/_gateway/me?app=<应用id>"

# 应用侧身份：guest / unavailable 都算正常回答
curl -s "https://artifact.catsco.cc/<应用id>/api/whoami"

# 自建域名直连：不应再跳 /_auth/start
curl -s -o /dev/null -w '%{http_code}\n' https://<你的域名>/orders
```

浏览器再确认三件事：网关入口能正常渲染工作台；内嵌发布页里工作台正常显示；直连域名顶层打开不再出现「404 页面暂时无法显示」。

## 七、后续同步上游的注意点

这 4 处都是**部署差异**，上游每次改到同名位置都会冲突。建议单独维护一个 `deploy/` 目录存放本补丁，同步上游后立刻重打，并在合并时逐条确认：

1. 帧头是否又加回 `X-Frame-Options` / `frame-ancestors`；
2. 首页跳转是否又变回绝对路径；
3. 握手是否又变成无条件顶层跳转；
4. 侧栏登录链接是否又变成无条件显示。
